- AI chat uploads go only through `/api/r2-upload` purpose=chat (`chat-upload.server.ts`): the server derives the role folder and key (`ai-chat-uploads/<folder>/<auth uid>/…`), writes `ai_chat_uploads` with the caller's RLS (role folder + Owner read, uploader/Owner delete, trigger-stamped uploader), and an optional record link is a second object + row in the existing document table — never a shared key or a widened document policy.
- Chat folders render only through `ChatUploadsBrowser` (chat sheet and /documents tab); open/delete reuse `useOpenDocument` and `r2DeleteDocument`; the model receives only the upload UUID marker from `attachmentModelText`, never storage keys.
