- CRM notifications = one crm_notifications event store, written only by SECURITY DEFINER triggers through crm_notify (unique dedupe_key, aggregate flag for repeating errors) and auto-resolved via crm_notification_resolve; visibility = audience (role/user) AND source-row RLS (crm_notification_source_visible), because one event must yield one in-app notice that never reveals a record the reader cannot open.
- New event types add a DB trigger and keep bodies free of personal/customer content where the source is not client-readable (e.g. quote_requests); delivery timing (immediate vs daily) is computed in model.ts, not stored.
