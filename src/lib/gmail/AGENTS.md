- CRM mail association uses exact normalized contact emails and saved contact-company relations; never pick a company by domain or overwrite historical CRM fields during sync, because ambiguous candidates need human review.
- Manual thread-company edits and sends validate user-visible CRM relations; cached Scarlet/Timothy reads retain account ownership filters, because shared threads do not grant every account's message content.- Historical mail→company relink is a read-only dry-run (`src/lib/gmail/relink-analysis.ts`); the incremental sync checkpoint only advances when every new message was processed, so failures are retried instead of skipped.
- Threads saved to the own Viba-Team company are analyzed as separate self_* relink categories, never as correctly linked, because outbound prospecting was historically attached to our own company.
- Campaign drafts: email_campaigns writes go through the user client (RLS + email_campaigns_guard trigger); recipients and the prechecked status are written only server-side after runCampaignPrecheck, because eligibility must never be client-supplied. prechecked is not a send permission.
- Marketing evidence reuses relink-analysis SENT/DRAFT and three-account guards; a completed cache scan cannot prove complete Gmail history, so absence stays uncertain and replies require a later exact recipient in the same owner/thread.
- Quote sends are checked server-side by `quoteSendBlocker` (status, kind, net > 0, no mismatch, priced/offer attachment) before the send log; reply-in-thread sends only the threadId and the server derives In-Reply-To/References from the sender's own Gmail thread metadata, so clients cannot forge reply headers.
- After a confirmed, non-duplicate, warning-free quote send the UI schedules the followup via `quote_schedule_followup` and advances quote_prep/follow_up → quote_sent via the shared Pipeline status mutation (`postSendPlan`); partial results are shown, never retried silently.
