
- Lead writes from the UI go through `useUpdateLead` (workspace) or `pipeline-detail-sheet` mutations; both must invalidate ["leads"] and ["pipeline"] and log activity — keeps the two paths in sync.
- Lead won transition only via `sales_mark_won_with_project` (owner or assigned sales, status=contract, valid PM); won is terminal — DB triggers enforce it, UI must not duplicate timestamps (lost_at/won_at set by DB).
- users_profile Gmail token columns are column-revoked from client roles; read/write them only via the server admin client, and never use select("*") on users_profile from the browser — it fails.
- Cross-user live refresh lives in `src/hooks/use-realtime-sync.ts` (mounted once in `__root`); add new shared tables there instead of per-page subscriptions — one channel, debounced invalidation.
- Project statuses are delivery-only (`PROJECT_STATUS` in viba-constants, mirrored by `projects_status_viba_check`); sales stages belong to leads. Won-lead quotes/followups/contact are linked to the project by the `projects_link_lead_records` trigger, never copied.
- The persistent AI panel (`src/components/ai/ai-panel.tsx`) and the /ai-assistant page share `src/components/ai/chat-shared.tsx` (per-user localStorage threads, agent meta, bubbles); record context comes only from the URL (`src/lib/ai-panel-context.ts`) and data is fetched by AI OS tools — one chat system, no parallel AI layer.
- AI approvals are immutable lifecycle rows in agent_run_steps, claimed atomically through service-only RPCs after authenticated owner/agent/tool checks; both chats use useAiApprovals, never replay model history to approve. Unconfirmed execution cannot be retried — prevents duplicate effects and false success.
- Mailbox lists use authenticated `mailbox.functions.ts` wrappers over security-invoker SQL pagination; membership comes from sync ownership/access, and folder labels only from messages owned by that account, because shared-thread labels are not account-specific.
- Large record selectors use RecordCombobox and authenticated crm_record_search (security invoker, allowlisted sources/filters); selected IDs are fetched separately, preserving RLS and existing mutation payloads without full option downloads.
- R2 file access is authorized server-side: keys are generated by `/api/r2-upload` (rules in `src/lib/r2-policy.ts`), signed download links only for keys owned by a document/attachment row the caller sees via RLS, deletes only via `r2DeleteDocument` (row first, then file) — clients never choose or sign arbitrary keys.
- Owner KPIs (/today OwnerHome and /dashboard) come only from `src/lib/owner-kpis.ts` via `OwnerKpiStrip`; quote value = net from quote_items, Budapest day bounds — keeps both owner pages consistent.
- `quote_requests` has RLS with no client policies; read/write only server-side (CRM viewer-role check in `quote-requests.functions.ts`, HMAC receiver) — website leads must not be reachable via the Data API.
- Sales daily lists, todo buckets and Sales/owner pulse counts share `useDailyWork` and `dailyWork`; scoped paginated lead reads and Budapest bounds prevent divergent counts without changing database views.
- Sales Today overview supplements `useDailyWork` with an own won count and company names; presentation-only `salesOverview`/`salesFocusSections` provide strict sent-quote KPIs and priority deduplication, while default owner/todo rendering and daily buckets remain unchanged.
- Completed preparation activities use authenticated `recordPrepActivity` with existing user RLS and a server-only timestamp; strict inputs prevent client dates and completed meetings on this path.
- Sales lead visibility = assigned_to only (`src/lib/sales/lead-visibility.ts`, mirrored by RLS `leads_select_sales`); unassigned leads are owner-only — keeps UI lists, deep links and DB consistent.
- Quote access = `can_access_quote` (owner; sales via assigned lead/project lead; PM via own project; unlinked = creator); totals are DB-trigger computed and new drafts/versions only via `quote_create_draft` RPC — one source of truth for permissions and amounts.
- Quote sending goes only through `/api/gmail/send` with `quote_id` + idempotency key (server writes `quote_sends`, marks sent/locks only after Gmail success); Gmail-sent mails are linked via `quoteLinkSentEmail` — one send path, auditable proof.
- Quote send evidence is database-enforced; linking verifies a live own-account Gmail SENT message, versions copy template fields from their exact source, and print contact comes only from the saved quote selection — prevents false sends and cross-alternative/customer substitutions.
- Quote detail workspaces reuse the existing panels and keep inactive tabs mounted but hidden; draft inputs must survive tab changes without introducing parallel save, send, or PDF paths.
- Quote creation choices and detail visibility use the existing quote_kind field and four workflow steps; received budgets never mount the own template/item editor, and legacy locked quotes allow a local display choice without database writes.
- Quote preview and print share QuotePrintDocument; general template defaults are owner-written settings snapshots behind authenticated role checks, never dynamically merged into saved quotes or locked documents.
- AI CRM account and lead context uses bounded `crm-read-page` envelopes with visible counts, stable pagination and source IDs; lead history first checks the user-visible lead before reading broader history tables, and model payloads never cut JSON silently — prevents false completeness and cross-lead context leaks without changing RLS.
- Timothy cached email reads resolve an explicit account through `crm_mailboxes`, enforce message owner and exact CRM/thread scope with the user client, and never refresh Gmail or use tokens; email-tool audit stores only source/completeness metadata, not content — avoids shared-thread exposure and duplicating private correspondence in AI audit.
- Timothy quote reads reuse quoteAmounts and summarizeActiveQuotes, page disjoint lead-linked/project-only company branches, and check both visible quote rows before same-scope comparisons or child reads — prevents parallel financial rules, duplicate won-lead quotes, and cross-case context leakage.
